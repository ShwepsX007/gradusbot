# Gradus: веб-терминал наблюдения

Веб-приложение использует ту же SQLite-базу, что и Telegram-бот: станции, настройка опроса бота, рынки, привязки, история и позиции видны обоим приложениям. Автоопрос открытой станции в веб-обзоре работает отдельно и не меняет эту настройку бота. При пустой базе показан явно обозначенный демонстрационный пример, который не записывается в базу.

## Запуск и защита

Терминал и все его API закрыты авторизацией; без файла настроек они отвечают 503. Вход — по логину и паролю, пароль хранится как scrypt-хеш, секрет сессий генерируется случайно. Изменённый через веб-интерфейс хеш хранится в таблице `web_auth_password` рабочей SQLite-базы и имеет приоритет над первоначальным хешем из файла окружения; пароль в открытом виде не сохраняется. Cookie с HttpOnly/SameSite, проверка CSRF-токена и Origin при изменяющих запросах, выход из интерфейса. Сессия действует до 12 часов; выход удаляет cookie в данном браузере, но украденную ранее копию cookie сам по себе не отзывает. Для отзыва всех сессий измените пароль или заново сгенерируйте файл с новым секретом и перезапустите службу.

**HTTP не шифрует пароль, cookie или содержимое терминала.** Их может перехватить или изменить любой, кто контролирует сеть. Используйте HTTPS с доменом или VPN. Если временно используется HTTP по IP, задайте уникальный длинный пароль, который нигде больше не используется, и осознавайте риск компрометации. По умолчанию cookie работает только с HTTPS; для HTTP параметр `--insecure-http` явно отключает Secure. Приложение не заменяет firewall и HTTPS.

Локальная установка и создание учётных данных (секретный файл должен быть вне Git; запрашивает пароль без отображения):

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python web/create_login.py /путь/вне/репозитория/gradus-web.env --insecure-http
# Прочитать файл без shell-подстановки символов $ внутри хеша:
python -c 'import os,sys; from dotenv import dotenv_values; os.environ.update(dotenv_values("/путь/вне/репозитория/gradus-web.env", interpolate=False)); os.execv(sys.executable,[sys.executable,"web/app.py"])'
```

Откройте http://127.0.0.1:8000. `WEB_HOST` и `PORT` задают адрес и порт. Для службы systemd укажите `EnvironmentFile=/etc/gradus-web.env`, используйте Gunicorn с одним worker и доступный firewall. Файл читается systemd от root, создаётся с правами 0600 и не должен храниться в репозитории, выводиться в чат или раздаваться пользователям сервера. Создание намеренно не перезаписывает существующий файл.

Ограничение входа: максимум пять попыток за 15 минут на IP в одном процессе, затем блокировка до истечения окна; успешный вход очищает счётчик этого IP. Счётчики в памяти сбрасываются при перезапуске; несколько workers, распределённые атаки и общий NAT снижают эффективность. Публичный сервер дополнительно следует защищать firewall/VPN и ограничением запросов на надёжном прокси. `WEB_TRUST_PROXY=1` включайте только если Gunicorn недоступен напрямую и доверенный прокси устанавливает X-Forwarded-For и X-Forwarded-Proto: иначе злоумышленник сможет подделать IP и схему. При прямом HTTP не включать эту опцию.

1. Добавьте станцию по ICAO и откройте её на обзоре: веб-опрос начнётся автоматически. Настройка опроса Telegram-бота для новой станции по умолчанию выключена.
2. Откройте «Найти рынок»: для известных ICAO терминал предлагает активные температурные события для связанного города. Для других станций использует название города, если оно задано по-английски или входит в список известных названий. Можно также искать по тексту или вставить ссылку `polymarket.com/event/...`. Сопоставление приблизительное: обязательно проверяйте правила и станцию разрешения. Привязка сохраняется в базе бота.
**Добавление по рынку:** на странице «Рынки» нажмите «Добавить по рынку» (либо «По рынку → станция» на обзоре), найдите событие или вставьте ссылку. Терминал читает `resolutionSource` и описания события/отдельных исходов Gamma API, ищет код в ссылке Weather Underground или явное указание ICAO/site и показывает основание. После проверки правил нажмите «Подтвердить и привязать»: существующая METAR-станция с таким кодом используется повторно, а новая создаётся с **выключенным опросом бота**. Стратегия не запускается; веб-опрос начинает работать при её открытии на обзоре. Для уже сохранённого рынка есть кнопка «Найти станцию». Если кода нет или найдены разные коды, автоматической привязки не будет: рынок можно сохранить отдельно и привязать вручную. По названию города станция не угадывается. При ручной привязке к выбранной станции терминал также предупреждает о несоответствии. Результат поиска — подсказка, а не гарантия: обязательно проверяйте правила каждого исхода, ссылку и доступность реальной METAR-станции. Значение METAR может отличаться от официального источника разрешения рынка.

3. Названия станций и рынков можно менять: название рынка обновляется во всех его привязках. В разделе «Рынки» доступны также рынки без привязок. Вкладки событий показывают индикатор Gamma, снимки стакана CLOB и позиции, сохранённые ботом. В каждой строке YES и NO: «купить» — минимальный ask (продавцы), «продать» — максимальный bid (покупатели); указанный объём — количество контрактов на лучшем уровне. Кнопка «Стакан» раскрывает до пяти лучших уровней bid и ask с ценой и количеством для каждого токена. На панели рынка можно отвязать событие от текущей станции либо удалить рынок из общей базы вместе с его историей и привязками ко всем станциям. В разделе «Станции» можно удалить станцию с её историей и привязками. При этом настройки соответствующих стратегий удаляются. Удаление блокируется при наличии связанной позиции в локальной базе, но открытые ордера на бирже не проверяются и не отменяются — проверяйте их самостоятельно.
4. Суточная кривая показывает местные сутки с 00:00 до 23:59: восход и закат соответствуют пересечениям с горизонтом. Форма линии — наглядная схема, а не астрономический график высоты светила. Стрелки переключают сегодня и шесть предшествующих местных дат. Температуры на линии — только сохранённые точки; на прошлых днях текущий маркер не рисуется. На некоторых датах нет восхода или заката (например, полярный день): в таком случае кривая недоступна. Шкала под дугой размечает местное время каждого часа, с подписями каждые три часа (на небольшом экране — реже). Цветные точки «МИН» и «МАКС» на дуге привязаны ко времени наименьшего и наибольшего значения среди доступных почасовых средних температур моделей за выбранные местные сутки; температура и время также приведены под шкалой в выбранных единицах. Если минимум и максимум повторяются, показано первое время. Это модель, а не измерение METAR или гарантия результата рынка. Для прошлых дат, если Open-Meteo вернул данные, показаны значения модели за дату, а не прогноз, сохранённый в тот день; при отсутствии почасовых данных точки не показываются. В дни смены времени повторяющийся местный час занимает одно место на этой схематичной шкале. Значок и текст в заголовке дуги показывают состояние по последней полученной сводке METAR (с её временем, если известно): облачность и указанные в сводке осадки или гроза. Отсутствие упоминания осадков не означает гарантированно сухую погоду. Для прошлой даты состояние не выдумывается, поскольку история погодного состояния не сохранялась. Если данные METAR или фаза дня неизвестны, это явно обозначается.
5. При открытии METAR-станции терминал запрашивает у AviationWeather.gov архив сводок за последние 7 суток (`hours=168`). Это работает независимо от настройки Telegram-бота; при открытом обзоре дополнительно запрашиваются текущий METAR и прогноз моделей. Для одного ICAO успешная загрузка повторяется не чаще раза в 15 минут, после ошибки — через пять минут; несколько вкладок и станций с одним кодом используют общий SQLite-кэш и блокировку запроса. Возможны пропуски: источник ограничивает запросы и количество результатов. При достижении 400 сводок выполняются дополнительные запросы к более раннему времени (до пяти страниц за попытку); если лимит или ошибка мешает завершить загрузку, она помечается как частичная. Доступность и полнота архива не гарантируются. Ошибка или ограничение показываются в интерфейсе, ранее сохранённые данные не выдаются за новую загрузку. Лимитер и backoff AviationWeather общие с текущим опросом внутри процесса веба; отдельно запущенный бот имеет собственный лимитер, поэтому их суммарные запросы также учитываются источником. На графике доступен выбор 24 часа / 48 часов / 7 суток; раскрываемый список содержит полученные архивные сводки, исходную строку и доступные температуру, точку росы и ветер. При неизвестном часовом поясе время показывается в UTC.

**Автоматический опрос в вебе.** Каждый видимый браузер на странице «Обзор» автоматически запрашивает только выбранную станцию; при переходе на другую станцию начинает запрашиваться новая. При переходе на другую страницу терминала, скрытии вкладки или закрытии браузера новые автоматические запросы погоды из этого браузера прекращаются. После возвращения станция загружается снова. Уже начатый запрос может завершиться после ухода со страницы. Если обзор открыт на другом устройстве или в другой вкладке, его запросы продолжаются независимо; терминал не выключает станцию для других зрителей. Ручной запрос Gemini может отдельно обновить данные своей станции. Это не фоновая служба и не включает автоматическую торговлю.

Браузер проверяет обновление примерно раз в 60 секунд; серверный кэш текущего METAR действует не менее 60 секунд и может действовать дольше в зависимости от настройки интервала. В одном веб-процессе запросы одной и той же станции используют общий кэш и блокировку; архив за 7 дней и stationinfo используют отдельные кэши и могут создавать дополнительные запросы. Лимитер и паузы AWC уменьшают нагрузку, но не гарантируют отсутствие ограничений или бана. Несколько разных открытых станций, другие веб-процессы и отдельный бот увеличивают суммарную нагрузку.

Автоопрос веба **не изменяет** общий `enabled` станции в SQLite. Переключатель «Опрос бота» по-прежнему меняет именно эту настройку, после подтверждения, и не приостанавливает автоопрос открытого обзора. Если Telegram-бот отдельно запущен, ранее разрешённые в нём станции могут опрашиваться независимо, а их стратегии и защитные действия могут работать: проверьте настройки бота отдельно. Выключение станции для бота может остановить его наблюдение и защитные действия; не меняйте его настройку только ради веба без проверки. Статус на обзоре означает работу автоопроса веб-страницы, а не подтверждение свежести METAR или работы бота.

Архивный кэш хранится отдельно от истории бота и локально записанных терминалом данных. Записи архива старше 7 суток удаляются по времени наблюдения при запуске и следующих открытиях станции; SQLite обычно переиспользует освободившиеся страницы, но размер файла на диске может не уменьшиться сразу. При удалении станции её архив удаляется, если не осталось другой станции с тем же ICAO. Локальные наблюдения терминала сохраняются как прежде восемь суток (для семи местных дат на суточной дуге), история бота остаётся отдельной. Совпадающие по времени архивная и локальная температура не дублируются; приоритет у локального наблюдения. После закрытия страницы веб-терминал сам не опрашивает станцию, но при следующем открытии может восстановить доступные у источника сводки за 7 суток; данные старше 7 суток из этого кэша не восстанавливаются.

График использует фактическое время сводки METAR, а не время опроса ботом, поэтому точки истории бота на нём не рисуются. Сетка — 1 °C с соседним °F и местные получасовые деления; график прокручивается по горизонтали. Минимум и максимум относятся только к доступным точкам выбранных 24 часов, 48 часов или 7 суток, не обязательно к местным суткам или официальному разрешению рынка. Наведение, касание или стрелки клавиатуры выбирают реальные точки. Линия не соединяет пропуски более двух часов; соединение меньшего промежутка не означает измерений между точками. Значения за пределами −150…+150 °C на графике не отображаются. Данные восхода и заката сохраняются отдельно при успешном запросе Open-Meteo; на суточной дуге сохраняется семидневная навигация и добавляются доступные точки архива.

В настройках единиц температуры доступны °C, °F или оба значения. Эта настройка общая с ботом; все вычисления и хранение исходных температур остаются в °C. Названия диапазонов исходов Polymarket показаны как в источнике и не пересчитываются.

## SSH-туннель и смена пароля

По умолчанию прежний HTTP-доступ и работа терминала не меняются. Чтобы включить смену пароля, нужно **отдельно настроить** режим `WEB_TUNNEL_ONLY=1`, запустить именно Gunicorn на `127.0.0.1:8108`, установить `WEB_TRUST_PROXY=0`, `WEB_COOKIE_SECURE=0` и подключаться к `http://127.0.0.1:8108` через SSH port forwarding. Приложение отказывает, если listener привязан к `0.0.0.0`, запрос пришёл не с локального адреса, host не `127.0.0.1` или включён доверенный прокси. Прямая выдача Gunicorn и всех маршрутов через публичный обратный прокси или другой TCP-посредник недопустима: такие локальные посредники могли бы обойти предположение о туннеле. Схема предполагает доверенный сервер и локальных пользователей; HTTPS браузера между устройством и прокси она не создаёт. Не открывайте 8108 для прямого доступа. Настройки службы не изменяются автоматически.

С устройства, где настроен SSH, откройте туннель и оставьте процесс запущенным:

```bash
ssh -N -L 127.0.0.1:8108:127.0.0.1:8108 root@78.17.66.215
```

После входа используйте «Настройки → Смена пароля». Нужен текущий пароль и новый не короче 16 символов. При смене отзываются все сессии и требуется повторный вход. Удаление строки `id=1` из `web_auth_password` серверным администратором вернёт пароль к первоначальному хешу в `/etc/gradus-web.env`; простой перезапуск или изменение хеша окружения не отменяет сохранённый в SQLite пароль. Берегите и резервируйте рабочую базу и файл окружения; не отправляйте содержимое файлов, пароли или ключи в чат.

## Торговый блок: ручные ордера и ограничения

Реальные заявки отправляются только через SSH-туннель, при включённой торговле и после подтверждения. Пользователь ранее проверил отправку ручной заявки; новый маршрут рыночных ордеров и новая политика независимых заявок проверены автоматическими тестами с настоящей локальной подписью SDK, но агент не отправлял реальные заявки на биржу. При первом запуске новой версии торговля выключается для повторного явного включения; перед работой обновите страницу. Старый формат FAK отклоняется, чтобы ранее введённое число долей не превратилось в сумму pUSD. Автоматической защиты позиции нет; уже выставленные ордера остаются на бирже после закрытия страницы и выключения торговли.

Торговый блок показывает снимок баланса, позиций и первой страницы открытых ордеров текущего CLOB-ключа. Снимки могут запаздывать или быть неполными, а доступный баланс может быть ниже показанного. Сопоставление не означает окончательный расчёт; подтверждённые и нерассчитанные сделки отображаются отдельно. В стакане показываются свои ордера и доступна отмена. Ордера из других ключей могут не отображаться; проверяйте Polymarket. Отмена не отменяет исполненную часть, а неясный результат отмены не означает, что она произошла.

Для купленной позиции **«Продать доли»** заполняет черновик SELL, количество позиции с округлением вниз до 0,01 доли и лучший BID, если он есть. Данные не являются атомарной резервацией и могут устареть; выберите лимитный или рыночный тип, проверьте количество и цену. Для подготовки нужен снимок не старше 65 секунд. Нажатие не отправляет ордер.

- **Лимитный GTC**: BUY или SELL, цена в центах и количество в долях. Проверяются шаг цены и минимум стакана. Ордер может исполниться сразу, частично или остаться в книге до отмены.
- **Рыночный FAK**: BUY задаётся суммой pUSD, SELL — количеством долей. Введите защитную цену в центах: максимум для BUY или минимум для SELL. Оценка берётся только по доступным пяти уровням стакана и не гарантирует исполнения. Доступная часть может исполниться; остаток FAK отменяется. При смене единиц ввода количество очищается. Защитная цена и сумма **без комиссий**: комиссии могут изменить итоговые расходы или поступления.

CLOB самостоятельно проверяет баланс, разрешения, минимум и доступность рынка; сервер не обходит эти ограничения и не увеличивает введённый объём. Цена может стать **строже на один шаг**, если округление SDK иначе нарушило бы указанную защитную границу. Сервер проверяет точные целочисленные суммы в подписанном рыночном ордере и не отправит его, если граница нарушена. Рынки с Protocol V2 position ID / Exchange V3 не поддерживаются этим маршрутом.

Можно разместить несколько независимых заявок по одному исходу, независимо от наличия открытого или ещё не сверенного принятого ордера. Если предыдущий результат неизвестен либо другая отправка ещё выполняется, перед новой заявкой появится **отдельное предупреждение и подтверждение**. Проверьте все ордера и сделки на Polymarket: новая заявка может привести к повторной покупке или продаже. Повторный POST с тем же nonce невозможен; таймаут или неясный ответ автоматически не повторяются. Заявки внешних приложений и ключей терминал может не видеть.

### Настройка аккаунта и переключатель

Через SSH-туннель в настройках можно сохранить приватный ключ подписанта, тип подписи и funder. CLOB API key/secret/passphrase можно ввести вручную или попытаться получить автоматически по подписанному запросу Polymarket с nonce 0. Для этого сервер обращается к Polymarket от имени подписанта и может создать API-ключ; рабочий доступ и совместимость с конкретным типом кошелька при сохранении не проверяются. Выберите правильный тип подписи и funder по данным своего аккаунта. Нужен пароль терминала. Это **не** seed-фраза; после сохранения поля очищаются, секреты через API не возвращаются. Никогда не отправляйте ключи или пароль в чат.

В интерфейсе подсказка под каждым полем объясняет источник значения. Для типов 1–3 funder — полный публичный адрес торгового кошелька из меню профиля Polymarket (0x и 40 шестнадцатеричных символов), а не приватный ключ MetaMask. Профильный кошелёк может отличаться от MetaMask и хранить пополненный баланс. Сам способ пополнения или вход через MetaMask не определяет тип подписи. Для старых аккаунтов с внешним подписантом возможен Safe (2); для новых — Deposit Wallet (3). Проверьте свой тип по данным аккаунта и документации Polymarket; его нельзя надёжно вывести только из даты входа. Для прямого EOA (0) поле funder должно быть пустым.

Для защиты подтверждения пароля действует ограничение: до пяти неудачных попыток за 15 минут на адрес в одном процессе; после этого пароль будет заблокирован до истечения окна. Правильный пароль очищает счётчик перед проверкой остальных полей, поэтому неверный funder или сбой получения CLOB-ключей не должны расходовать попытки пароля. Счётчики в памяти общие для пользователей с одного адреса и сбрасываются при перезапуске процесса; несколько workers снижают надёжность ограничения. В режиме SSH-туннеля разные устройства могут иметь один loopback-адрес.

**Секреты хранятся на сервере без шифрования** в `.gradus-private/account.json`, каталог 0700 и файл 0600 принадлежат пользователю службы и исключены из Git. Root и пользователь службы могут прочитать ключи; компрометация сервера грозит потерей средств. SSH защищает канал, но не диск. Для замены необходим полный комплект; удаление файла не гарантирует стирания из бэкапов и не отменяет ордера или позиции.

При обновлении с прежней версии и при первом запуске отправка заявок выключена; включать её нужно заново. Пользователь проверил ручной BUY; новый рыночный маршрут агент на реальной бирже не проверял. Автоматической защиты позиции нет; фоновая сверка работает только при запущенной службе. Для включения требуется явное подтверждение и пароль в настройках через SSH; настройка сохраняется после перезапуска, при изменении или удалении ключей выключается. Выключение блокирует новые отправки, но не отменяет уже размещённые заявки и не гарантирует остановку запроса, который уже начался. Ручная отмена остаётся доступной и после выключения. Отмена не возвращает уже исполненную часть; если её результат неизвестен, проверяйте Polymarket. Не публикуйте локальный listener через прокси или TCP-посредник: такая схема может обойти проверку туннеля.

### Фоновое наблюдение за аккаунтом (только чтение)

Независимый процесс с настраиваемым интервалом (по умолчанию 30 секунд, от 15 до 300) сохраняет в ту же SQLite-базу снимок счёта: баланс CLOB, первую страницу позиций Data API v2 и первую страницу открытых ордеров CLOB. Он работает и после закрытия браузера, **не отправляет и не отменяет ордера**, не устанавливает SL или тейк и не исполняет заявки вместо биржи. Он также выполняет ограниченную сверку веб-ордеров и их сделок (подробнее ниже). После каждой ошибки предыдущий снимок не выдаётся за актуальный; состояние «устарел» появляется после трёх интервалов без обновления, но не раньше 90 секунд. Увеличение интервала не делает старый снимок свежим. В торговом блоке баланс, позиции выбранного события, цены, PnL и лучшее BID отображаются из снимков и могут запаздывать; BID тоже снимок стакана. При отсутствии данных показывается недоступность, а не ноль. Снимки данных аккаунта и отпечаток настройки сохраняются в общей базе бота — защищайте её, как и другие личные данные.

Служба не устанавливается автоматически при обновлении. На сервере с путём `/opt/gradusbot-web` и пользователем службы `gradus-web` после обновления запустите:

```bash
sudo install -m 0644 /opt/gradusbot-web/web/gradus-position-monitor.service /etc/systemd/system/gradus-position-monitor.service
sudo systemctl daemon-reload
sudo systemctl enable --now gradus-position-monitor.service
sudo systemctl --no-pager --full status gradus-position-monitor.service
```

Шаблон проверяет `/opt/gradusbot-web/.venv/bin/python` и `/opt/gradusbot-web/venv/bin/python`; если виртуальное окружение расположено иначе, настройте путь запуска отдельно. Служба не подменяет и не меняет `gradus-web`; блокировка исключает два локальных экземпляра. Проверка: `journalctl -u gradus-position-monitor -n 50 --no-pager`. Отключение: `sudo systemctl disable --now gradus-position-monitor.service`. После обновления кода или окружения перезапустите также `sudo systemctl restart gradus-position-monitor.service`. Если сервис не запущен или старый снимок, на панели это указано; зелёное или свежее состояние **не означает, что стоп защищает средства**.

### Сверка и ограничения

Кнопка «Сверить с биржей» получает баланс обеспечения CLOB (pUSD), первую страницу позиций Data API v2 и первую страницу открытых ордеров CLOB. Снимки могут запаздывать и быть неполными: отсутствие строки не доказывает отсутствие ордера или сделки. «Принят CLOB» не означает исполнение. «Сопоставлено» (`size_matched`) не означает окончательное исполнение или обновление баланса.

Каждая попытка ручной отправки записывается в SQLite до единственного POST. До отправки сервер проверяет поля подписанного ордера и сохраняет его расчётный EIP-712 hash, **не сохраняя подпись или приватный ключ в журнал**. Требуется `py-clob-client-v2==1.2.1`; маршрут подписывает только ордера CTF Exchange V2 с legacy token ID и не поддерживает Protocol V2 position ID / Exchange V3. Если версия SDK, поля или локальный hash не могут быть проверены, отправки нет. Успешный ответ с другим ID считается конфликтом и блокируется. Сетевой таймаут и непонятный ответ не вызывают повторного POST; отсутствие ордера по запросу не доказывает, что он не был отправлен.

Служба фонового монитора и запрос журнала по очереди проверяют до трёх несверенных веб-ордеров за проход: точный ID, исход, сторону, владельца, цену и объём, затем связанные сделки по ID. Для рыночных ордеров используются сохранённые подписанные количества и цена; при расхождении результат остаётся непроверенным. Для maker используется `matched_amount`, для taker — размер сделки. Сумма сделок должна совпадать с `size_matched`; `MATCHED`, `MINED`, `RETRYING` и другие промежуточные статусы не считаются окончательными. Отдельно показываются суммы `CONFIRMED` и `FAILED`. Не более 100 связанных сделок на ордер; при неполных данных, сетевой ошибке или неожиданном статусе результат остаётся непроверенным. Монитор не продаёт и не покупает.

При неизвестном результате, конфликте ID, смене ключей или недоступной истории сверка может не восстановить статус. Перед новой заявкой проверьте Polymarket и принимайте решение отдельно; подтверждение не доказывает, что предыдущий ордер не исполнился. Не редактируйте базу для обхода проверок. Журнал ограничен 100 записями с приоритетом незавершённых.

Эта защита охватывает журнал данного терминала, а не все действия на аккаунте. CLOB-ключи могут не видеть ордера других ключей; внешние приложения, сайт, другие экземпляры терминала, транзакции в пути и запаздывающие позиции могут изменить доступный объём. Не считайте эту реализацию гарантией отсутствия двойной продажи. Стоп-лосс и автоматический тейк для BUY не реализованы; прежний план их автоматической привязки отменён. Существующие механизмы Telegram-бота не подключены к ручной торговле.

## Сканер температурных рынков

На странице «Рынки» нажмите **«Сканировать»**. Сканер запрашивает активные незакрытые события Gamma с тегами `daily-temperature` и `temperature` (это разные теги), удаляет дубликаты и показывает ссылку на правила и источник. Доступность события не означает, что заявки принимаются; если Gamma явно сообщает об остановке заявок, это отмечается. Каталог ограничен пятью страницами по 100 событий на каждый тег и общим временем запроса; при достижении лимита или сбое выводится предупреждение о неполном списке. Снимок кэшируется на 120 секунд: повторное нажатие в этот период не гарантирует обновление каталога.

Для однозначного ICAO кода источник — правила рынка (в том числе `ids` официального METAR API AviationWeather или ссылка Weather Underground); координаты запрашиваются у AviationWeather пакетами, а часовой пояс — у Open-Meteo по координатам. При ошибке или неоднозначности часовой пояс не угадывается по названию города. Исключение: для рынка Гонконга со ссылкой на Hong Kong Observatory показывается `Asia/Hong_Kong`, но METAR-станция не назначается. Остальные события с неизвестной зоной показываются внизу. Дата локальных суток берётся только из распознанного slug, не из поля завершения Gamma; иные события также остаются в списке с пометкой.

Сохранённые рынки находятся вверху страницы, перед сканером. В карточке сканера показаны до трёх исходов с наибольшей **ценой YES** и отдельно исход с максимальным расчётным десятичным коэффициентом `1 / цена YES` (это наименьшая ненулевая цена, а не наибольший процент). Берутся только явно обозначенные YES из `outcomePrices` Gamma; закрытые исходы и исходы с приостановленным приёмом заявок исключены, при неизвестном статусе приёма отображается пометка. Нулевая цена может отображаться в списке, но коэффициент для неё не рассчитывается. Данные — снимок из ответа Gamma, не стакан и не гарантированная цена покупки: спред, глубина, доступность заявок и комиссии не учитываются. Показывается время снимка; после двух минут он помечается устаревшим. Новое сканирование не гарантирует обновления до истечения серверного кэша. Реальные цены заявок YES/NO проверяйте в стакане открытого рынка.

Карточка сравнивает текущее время и дату источника со временем устройства, включая летнее время; сортировка разделяет текущие местные сутки, будущие и прошедшие, а внутри групп ставит более ранний местный час выше. Неопределённые даты и часовые пояса — ниже. Время и порядок обновляются каждую минуту при открытой странице. Это **не** таймер закрытия или разрешения события: прошлые сутки могут ещё оставаться активными, а будущие пока не начались.

Кнопка «Добавить» заново проверяет правила и, при совпадении надёжного источника с карточкой, привязывает рынок к существующей станции или создаёт новую **выключенную**. Перед сохранением сервер ещё раз перечитывает правила и отклоняет изменившийся код. При изменении показанного источника или менее однозначном указании кода запрашивается подтверждение. Если код не найден либо коды конфликтуют, сохраняется только рынок: для ручной привязки выберите станцию и добавьте ссылку в диалоге привязки. Никакая станция для альтернативного источника не создаётся автоматически. Обязательно сверяйте правила Polymarket: данные METAR в терминале могут не совпадать с окончательными данными разрешения.

## Источники и ограничения

- Стрелки над точками дуги показывают рост или снижение относительно предыдущего сохранённого по времени значения, включая предшествующую дату; при равной температуре или отсутствии предыдущего значения стрелки нет. На дуге совмещаются локальные METAR, доступный архив за 7 суток и история опросов Telegram-бота, если она есть; отсутствующие у источников наблюдения не выдумываются.
- METAR: AviationWeather.gov через существующую `utils.fetch_metar`, включая кэш, лимитер и backoff при 403/429. Веб-терминал также кэширует ответы минимум на 60 секунд. При открытом обзоре текущая выбранная станция опрашивается независимо от настройки бота; при открытии также может выполняться ограниченный запрос архива METAR. Влажность рассчитана по температуре и точке росы; ветер переводится из узлов в м/с (1 узел = 0,514444 м/с). Облачность расшифровывается по наибольшему слою покрытия METAR. Состояние осадков — из последней сводки, с её временем; отсутствие упоминания не доказывает отсутствие осадков. Вероятность осадков Open-Meteo — прогноз на текущий часовой интервал по местному времени, включающий дождь, снег и другие осадки более 0,1 мм; порог 60% для пометки «высокая» условный. Время наблюдения также содержится в исходной строке METAR.
- Прогноз температуры: Open-Meteo, MET Norway Locationforecast и, при настроенном ключе, OpenWeather One Call 3.0. Координаты берутся из AviationWeather stationinfo, а при его недоступности — из сохранённой сводки METAR, если там были координаты. При отсутствии координат, часового пояса или ответа сервисов интерфейс указывает причину. Прогнозы запрашиваются для станции, открытой в активном обзоре, и при ручном запросе Gemini. Часовой пояс предоставляет Open-Meteo, ранее сохранённые сведения или OpenWeather; восход/закат — Open-Meteo либо сохранённые сведения. Если пояс неизвестен, экстремумы местного дня не вычисляются.
- Среднее: для каждого момента рассчитывается простое среднее доступных температур Open-Meteo, MET Norway и OpenWeather. При несовпадении сеток (например, часовой пояс с 30-минутным смещением) MET Norway и OpenWeather линейно интерполируются между соседними точками максимум в одном часе; экстраполяции нет. Если за конкретный час есть только один источник, берётся он, а не ноль. Минимум и максимум — экстремумы получившегося ряда за доступные часы местных суток; рядом указаны источники и их значения для этих моментов. Это **не среднее отдельных суточных минимумов и максимумов**. MET Norway предоставляет текущий прогноз, а не архив прежних прогнозов: уже прошедшие часы могут быть только из Open-Meteo или вовсе отсутствовать. Для прошлых дат Open-Meteo возвращает данные модели, а не прогноз, сохранённый в тот день. Неполные сутки могут исказить экстремумы; источники могут использовать общие модели, и усреднение не гарантирует повышения точности. Это не измерение METAR, вероятность или гарантия разрешения рынка.
- Open-Meteo кэшируется на 15 минут в процессе веба. MET Norway кэшируется в SQLite не менее 15 минут и до указанного сервисом `Expires`; используется условный запрос `If-Modified-Since`, при ограничениях — пауза с учётом `Retry-After`. Просроченный прогноз не выдаётся как свежий. Источник MET Norway: [Norwegian Meteorological Institute](https://api.met.no/weatherapi/locationforecast/2.0/documentation), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); данные изменены интерполяцией и усреднением. Вероятность осадков и времена восхода/заката остаются данными Open-Meteo, они не усредняются.
- События и индикативные цены: Polymarket Gamma API. Показатель Gamma относится к первому исходу в исходных данных, а не к цене исполнения. Публичный [CLOB API](https://docs.polymarket.com/market-data/prices-order-books) предоставляет снимки стакана для токенов, явно обозначенных Gamma как YES и NO. Обновление при открытой странице примерно раз в 30 секунд, серверный кэш 20 секунд; до 100 токенов на событие (дальнейшие не запрашиваются и помечаются). При ошибке или отсутствии данных стакан не выдумывается. Показывается до пяти лучших уровней; объёмы не являются числом людей или их совокупными позициями. YES и NO могут отображать связанную ликвидность, её нельзя суммировать. Котировки могут измениться до исполнения и не включают комиссии; это не поток в реальном времени и не гарантия цены. Существующие позиции — только из локальной базы бота, а не все позиции участников. Поиск может возвращать и непогодные события — проверяйте правила, дату, источник разрешения и соответствие станции самостоятельно.
- Лимитер AWC в боте и веб-сервере **раздельный**, так как это разные процессы. Настройте суммарную частоту с запасом; несколько веб-процессов или серверов увеличат нагрузку. Доступ к METAR с других клиентов тоже учитывается поставщиком. Настройки расписания заданий бота могут требовать его перезапуска.
- Ручной BUY пользователь проверил; новая реализация рыночных ордеров и сверки не проверялась агентом на реальном аккаунте. Автоматическая защита позиции и защита от всех внешних операций не реализованы. Снимки аккаунта могут быть неполными или запаздывать; детали и риски — в разделе торговли выше.

Проверки: `python -m unittest discover -s tests -v` и `node tests/test_weather.js`. Дополнительный UI smoke test: `npm install --prefix .cache/ui-test jsdom@22` и `NODE_PATH=.cache/ui-test/node_modules node tests/test_temperature_scan_ui.js`.

## Копирование: только наблюдение и предварительная оценка

Страница «Копирование» предназначена **только для публичного наблюдения**. Она не использует торговые ключи аккаунта, не отправляет и не отменяет реальные заявки, не создаёт виртуальных ордеров и позиций и не считает прибыль. Она не является автоматическим копированием сделок и не защитит позицию. Автоматическая защита позиции отсутствует; ручные ордера отправляются отдельно.

Можно добавить до пяти публичных трейдеров по адресу, ссылке профиля `polymarket.com/profile/0x…` или `polymarket.com/@имя`, либо точному имени. Gamma должен однозначно подтвердить торговый `proxyWallet`; при неоднозначности введите адрес. Наблюдение начинается с момента добавления (сделки той же секунды также исключаются). При паузе/возобновлении пропущенный период **не обрабатывается**. Удаление удаляет и сохранённую историю этого трейдера. Эти действия и чтение данных доступны только через SSH-туннель с авторизацией и CSRF-защитой.

На каждое публичное исполнение BUY независимо вычисляется размер: фиксированная сумма pUSD, то же число долей или указанный процент от долей трейдера. Дополнительный потолок pUSD ограничивает только **этот расчёт**, а не реальные расходы или суммарный риск. Оценка сопоставляет цену трейдера с объёмом первых пяти уровней доступного снимка стакана, без гарантий исполнения, учёта комиссии, минимального размера и точности округления. На каждый проход скачивается стакан не более чем для 10 разных исходов, для остальных отмечается недоступность. Продажи трейдера отображаются, но размер пропорционального выхода не вычисляется: виртуальная позиция и доля его позиции пока неизвестны. Время ожидания N, исполнение/отмена виртуальных лимитных ордеров, общие лимиты на трейдера/рынок, портфель и PnL пока не моделируются.

Интервал опроса каждого трейдера — 15–300 секунд; служба работает независимо от браузера, но реальные задержки могут быть больше. Читается публичный `/v2/trades` с `taker_only=false` и до 10 страниц по 100 записей. Не более 200 новых событий за один проход; при неполных, некорректных или слишком объёмных ответах показывается ошибка, проход не записывается и повторяется позже. При переполненной ленте можно остановить и снова включить наблюдение, однако пропущенный период будет потерян. Перекрытие успешных опросов составляет пять минут; сделки, появившиеся позже этого окна, могут быть пропущены. Общественная лента не предоставляет надёжного уникального ID каждого исполнения: одинаковые строки учитываются по их количеству в ответе, дубликаты или пропуски возможны при изменении публичной ленты и пагинации. Хранится до 5000 сигналов на трейдера, показываются последние 100; более старые записи удаляются. Нельзя использовать этот журнал как надёжный журнал исполнения или автоматической торговли.

Службу нужно установить отдельно (путь `/opt/gradusbot-web`, пользователь `gradus-web`):

```bash
sudo install -m 0644 /opt/gradusbot-web/web/gradus-copy-observer.service /etc/systemd/system/gradus-copy-observer.service
sudo systemctl daemon-reload
sudo systemctl enable --now gradus-copy-observer.service
sudo systemctl --no-pager --full status gradus-copy-observer.service
```

После обновления службы перезапустите `sudo systemctl restart gradus-copy-observer.service`. Журнал: `journalctl -u gradus-copy-observer -n 50 --no-pager`; отключение: `sudo systemctl disable --now gradus-copy-observer.service`. Сигнал службы устаревает через 90 секунд, но при долгих сетевых запросах она может временно казаться остановленной. Файл блокировки `.gradus-private/copy-observer.lock` нельзя удалять, пока служба работает. Данные наблюдения хранятся в SQLite терминала; доступ к базе следует ограничить.

## OpenWeather One Call 3.0

Это отдельная подписка OpenWeather, не тариф 5 day / 3 hour. После обновления терминала подключитесь **через SSH-туннель**, войдите и откройте «Настройки → Прогноз One Call 3.0». Введите ключ и текущий пароль терминала, подтвердите сохранение. Существующий ключ повторно не показывается. Для удаления введите текущий пароль и нажмите «Удалить ключ»; это не отзывает ключ у провайдера. Не отправляйте ключ или пароль в чат. Сохранение не проверяет подписку; при 401/403 проверьте ключ, активацию и именно One Call 3.0 в кабинете. После ошибки или замены ключа сохраняется двухчасовая пауза для данной точки.

Прогноз запрашивается по координатам станции, не по названию города, при открытом обзоре или ручном запросе Gemini. Доступно до 48 почасовых значений; на панели «Прогноз на сегодня» можно раскрыть отдельный почасовой список OpenWeather. В статусе показаны доступность, время получения и ближайшая следующая попытка. Используются только доступные данные, и просроченный прогноз не выдаётся как свежий. На дуге и карточке экстремумы относятся к усреднённому ряду моделей, не к фактическому наблюдению METAR. Gemini получает ограниченные погодные поля и статус, но не получает ключ OpenWeather. Сохранённый ранее ответ Gemini не пересчитывается автоматически: для учёта нового источника запросите новый ответ вручную.

Кэш и лимитер хранятся в общей SQLite-базе: запрос по координатам (округлённым до 4 знаков) не чаще одного раза в 2 часа, даже при ошибке, после замены ключа и перезапуска. Одновременные вкладки/процессы с общей базой разделяют кэш и бронь запроса; попытка учитывается до сетевого вызова, включая таймауты и ошибки. В скользящем окне 24 часа терминал разрешает не более **900** собственных попыток. При HTTP 429 для всех координат устанавливается пауза не менее 2 часов с учётом более длительного `Retry-After`; автоматически повторный запрос внутри паузы не выполняется. Если обзор закрыт, отдельного фонового опроса OpenWeather нет; уже начатый запрос может завершиться. Другие устройства с открытым обзором и ручной запрос Gemini могут запускать запросы независимо.

**Стоимость:** согласно документации OpenWeather, первые 1000 запросов One Call в день бесплатны, последующие могут быть платными; проверьте действующие условия своего аккаунта. Локальные 900 попыток не видят использование этого же аккаунта другими приложениями или ключами и не гарантируют отсутствие расходов. В кабинете OpenWeather установите подходящий лимит запросов/расходов, контролируйте биллинг и учитывайте другие приложения. Часы работы провайдера и его дневная квота могут отличаться от локального скользящего окна.

Ключ хранится на сервере **без шифрования** в `.gradus-private/openweather.json` (каталог 0700, файл 0600), доступен root и пользователю службы; не включайте папку в Git и общедоступные копии. `.gradus-private/openweather.lock` нельзя удалять во время работы. Ключ передаётся в OpenWeather по HTTPS как параметр запроса; не включайте внешнее протоколирование полных URL запросов к OpenWeather, иначе оно может записать ключ. Локальное удаление файла не гарантирует стирания из резервных копий — при утечке отзовите ключ у провайдера. Документация: [One Call 3.0](https://openweathermap.org/api/one-call-3), [тарифы](https://openweathermap.org/price).

## Ручной прогноз Gemini

Под погодной дугой находится «ИИ-прогноз станции». Это ручной анализ: выберите станцию и нажмите «Получить прогноз», затем подтвердите отправку данных и возможные расходы. При открытии страницы, обновлении погоды и переходе между станциями новые запросы Gemini **не** выполняются. До сохранения ключа доступна только загрузка ранее полученного ответа. Встроенный промпт просит оценить минимум и максимум локальных суток, неопределённость и неполноту данных; его можно изменить в «Настройки → Модель, промпт и ключи».

1. На каждом устройстве подключайтесь к терминалу через уже настроенный SSH-туннель и войдите в терминал. Изменение настроек дополнительно требует текущий пароль терминала. Сам запрос и чтение сохранённого ИИ-прогноза тоже доступны только через туннель.
2. В настройках укажите модель, доступную вашему проекту (по умолчанию `gemini-3.5-flash-lite`), и промпт. Доступность, [тариф](https://aistudio.google.com/docs/pricing) и региональные ограничения проверяйте в Google AI Studio: модель по умолчанию не гарантирует бесплатный доступ.
3. Для каждого ключа введите **фактический Google Cloud Project ID** его проекта и API-ключ Gemini. Можно добавить до 8 ключей; сохранённые ключи не показываются и не возвращаются в браузер. Удаление ключа в терминале не отзывает его в Google. Если ключ скомпрометирован, отзовите или замените его в Google. **Не отправляйте ключи или пароль в чат.**
4. Квоты действуют **на проект**, а не на каждый ключ. Терминал не может проверить, какому проекту действительно принадлежит ключ: вы обязаны ввести точный ID. Два ключа одного проекта не создают две квоты; при 429 второй ключ этого же ID пропускается. Переключение на следующий проект происходит только если вы отметили в настройках, что имеете разрешение Google использовать квоты указанных проектов для общей нагрузки. Не используйте эту функцию для обхода установленных ограничений Google. Без подтверждения используется первый добавленный проект.

При HTTP 429 проект и модель ставятся на паузу минимум на 5 минут с учётом более длительного `Retry-After`/`retryDelay` Google. Пауза сохраняется в SQLite между перезапусками. Если разрешено переключение проектов, запрос может быть отправлен в следующий проект после подтверждённого 429. При ошибке доступа, недоступной модели, таймауте, обрыве, ошибке сервера или повреждённом ответе переключения и автоматического повтора **нет**. Неизвестный результат может быть платным. Проверьте расходы в Google и сохранённый ответ, прежде чем повторить запрос вручную. Одновременно на сервере допускается один запрос Gemini для всех станций; при перезапуске процесса блокировка снимается системой. Файлы `.gradus-private/gemini.lock` и `.gradus-private/gemini-request.lock` **нельзя удалять во время работы**.

Сервер отправляет Google только настраиваемый промпт и ограниченный снимок погодных данных выбранной станции: код и название станции, координаты, часовой пояс, актуальный и архивные METAR (до 1000 температурных точек за 7 суток и до 96 последних сводок), имеющиеся почасовые значения Open-Meteo, MET Norway и OpenWeather и статус источников. Некоторые поля могут отсутствовать; объём ограничен, интерфейс показывает количество точек, статус и возможную неполноту. При ручном запросе обновляются доступные погодные данные выбранной станции независимо от настройки опроса бота. Настройки торговли, ключи Polymarket, позиции и ордера не включаются. Режим Google Search не включён: у модели нет живого интернета и самостоятельной проверки новостей. Приписанные ИИ источники нужно проверять; ответ может содержать ошибки и не является официальным прогнозом или гарантией исхода рынка. Не используйте его как самостоятельный торговый сигнал.

Последний ответ хранится отдельно для каждой станции в SQLite и показывается не более 30 дней; очистка старых записей выполняется при запуске терминала и успешном новом запросе, а при удалении станции удаляется и её ответ. SQLite и резервные копии могут содержать текст ответа и введённую пользователем информацию; очистка записи не гарантирует физического стирания из базы или резервных копий. Ответ показывается как обычный текст; указана модель, проект, время, источники и обрезка ответа. Google может учитывать токены рассуждений, поэтому сумма видимых токенов текста не обязательно равна общему количеству. Цена определяется тарифом Google, числом токенов, включая внутренние рассуждения, и проектом. Сверяйте биллинг непосредственно в Google.

Ключи Gemini и промпт хранятся в `/opt/gradusbot-web/.gradus-private/gemini.json` (папка 0700, файл 0600) **без шифрования** и доступны root и пользователю службы. Не добавляйте эту папку в Git или общедоступные копии. При использовании бесплатного API Google условия могут позволять обработку содержимого запросов и ответов для улучшения продуктов, в том числе людьми; не добавляйте личные или конфиденциальные сведения в промпт и названия станций. Подробности: [условия Gemini API](https://aistudio.google.com/docs/terms), [лимиты](https://aistudio.google.com/docs/rate-limits), [модели](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite). Проверьте политику и расходы для каждого проекта до включения.

### Портфель

Страница «Портфель» доступна только через SSH-туннель и показывает снимок CLOB и Data API v2 без отправки сделок. Баланс и диаграммы остаются видимыми над вкладками «Позиции», «Открытые ордера», «Журнал заявок» и «История активности». Переключение вкладок не отправляет запросов и не изменяет ордера; выбранная вкладка сохраняется при обновлении снимка и возвращении на страницу. Баланс pUSD и оценка позиций получаются независимо, их сумма приблизительна. Диаграмма PnL за месяц — сумма реализованного и нереализованного PnL позиций, а не стоимость счёта. Данные могут запаздывать; отсутствующие значения не заменяются нулями. Распределение строится по доступной оценке открытых позиций; комбо-позиции могут не входить в диаграмму. Стоимость Data API может включать комбо по себестоимости.

Позиции и активность читаются до пяти страниц по 100 записей; при усечении выводится предупреждение. Открытые ордера CLOB также читаются с ограничением до пяти страниц, при усечении выводится предупреждение; журнал терминала показывает до 100 записей с приоритетом незавершённых. История активности — это не полный журнал ордеров; сопоставленная часть заявки не обязательно рассчитана. Депозиты и выводы включены в запрос активности, но отдельные типы могут отсутствовать в стандартной ленте API. Рынок открывается только по точной существующей привязке к станции; если подходящих привязок несколько, выбирает пользователь. Для непривязанного события предложен поиск привязки, при этом непогодная станция не угадывается.
